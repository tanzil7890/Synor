Synor uses an [LMDB](http://www.lmdb.tech/doc/) database to persist its internal state. This database tracks target states and [memoization](../programming_guide/function) results from previous runs, enabling Synor to detect what changed and apply only the necessary updates.

## Database path

Synor needs a database path (`db_path`) to know where to store this internal state. The simplest way to set it is via the `SYNOR_DB` environment variable:

```bash
export SYNOR_DB=./synor.db
```

You can also set it programmatically in a [lifespan function](../programming_guide/app#lifespan-optional):

```python
@syn.lifespan
def synor_lifespan(builder: syn.EnvironmentBuilder) -> Iterator[None]:
    builder.settings.db_path = pathlib.Path("./synor.db")
    yield
```

Or pass it directly when creating a [`Settings`](./multiple_environments) object:

```python
settings = syn.Settings(db_path=pathlib.Path("./synor.db"))
```

Setting `db_path` in the lifespan or `Settings` takes precedence over the `SYNOR_DB` environment variable. If neither is provided, Synor will raise an error.

## LMDB tuning

The LMDB database has two tunable settings, grouped under `syn.LmdbSettings` and attached to `Settings` as `db_settings`. The defaults work well for most use cases — you only need to adjust them for large-scale deployments.

| Setting | Default | Env Variable | Description |
|---------|---------|-------------|-------------|
| `max_dbs` | `1024` | `SYNOR_LMDB_MAX_DBS` | Maximum number of named LMDB databases. Must be &ge; 1. |
| `map_size` | `4294967296` (4 GiB) | `SYNOR_LMDB_MAP_SIZE` | Initial LMDB memory-map size. Must be &gt; 0 and is rounded up to the nearest OS page. |

### When to adjust

- **Set a larger initial `map_size`** when you know a bulk load will immediately exceed 4 GiB. Synor automatically adopts map growth published by another process and doubles the map after `MDB_MAP_FULL`; a durable resize lock serializes competing processes. Starting larger avoids resize retries but is not required for correctness. On 64-bit systems this is a virtual-address reservation, not immediate physical-memory allocation.
- **Increase `max_dbs`** if you have an unusually large number of apps sharing a single database directory.

All Synor read and write transaction entry points participate in the same
process-wide transaction coordinator. Resizing waits for local transactions to
drain, takes the cross-process resize lock, adopts any size another process has
already published, and only then grows when necessary. Do not open independent
LMDB write transactions around Synor's database files.

### Native-effect schema upgrades

Native-effect metadata currently uses schema version 4. Opening an app written
with versions 1–3 performs a one-time, atomic migration that validates existing
lineage cursors and builds transactionally maintained unresolved-effect and
query-verified-tombstone totals. A crash exposes either the complete older
schema or the complete v4 summary. Strict no-op completion is then constant
time with respect to retained effect history, while inspection, compaction, and
drop continue to scan and cross-check the underlying evidence before any
destructive action.

This is a one-way in-place upgrade. Take a consistent backup first, upgrade all
processes that share the environment together, and do not reopen a v4 database
with a v3 or older binary. Use the copy-only
`synor native-effects prepare-downgrade` workflow when an older binary is
required; it leaves the source database unchanged.

### Configuration

Via environment variables:

```bash
export SYNOR_LMDB_MAP_SIZE=8589934592   # 8 GiB
export SYNOR_LMDB_MAX_DBS=2048
```

Or programmatically in a lifespan function:

```python
@syn.lifespan
def synor_lifespan(builder: syn.EnvironmentBuilder) -> Iterator[None]:
    builder.settings.db_path = pathlib.Path("./synor.db")
    builder.settings.db_settings.map_size = 8 * 1024 * 1024 * 1024  # 8 GiB
    builder.settings.db_settings.max_dbs = 2048
    yield
```

Or when creating a `Settings` object directly:

```python
settings = syn.Settings(
    db_path=pathlib.Path("./synor.db"),
    db_settings=syn.LmdbSettings(
        map_size=8 * 1024 * 1024 * 1024,  # 8 GiB
        max_dbs=2048,
    ),
)
```

When using `Settings.from_env()`, the LMDB settings are automatically loaded from their environment variables if set; otherwise, the defaults apply.

:::note[Legacy keyword arguments]
For backward compatibility, `Settings` still accepts `lmdb_max_dbs` and `lmdb_map_size` as keyword arguments, and exposes them as attributes (e.g., `settings.lmdb_map_size = ...`). These read and write the same underlying values as `settings.db_settings.max_dbs` / `settings.db_settings.map_size`. Passing both `db_settings=` and the legacy keywords in the same `Settings(...)` call raises `ValueError`.
:::
